# RSVP 成功态稳定切换设计

## 背景与根因

宾客提交成功时，客户端立即隐藏约 788px 高的表单并显示约 281px 高的成功卡片。实测 RSVP 区域会从约 1032px 缩到约 525px，后续“婚礼当日见”区块一次上移约 507px；成功卡片同时沿用通用 `reveal` 动画，因此用户会看到明显的页面弹跳。

## 目标

- 提交成功后，RSVP 区域在当前页面停留期间保持切换前的高度，后续区块不突然上移。
- 成功卡片与标题作为一个整体在保留区域内垂直居中。
- 成功卡片直接稳定出现，不再次播放通用 reveal 位移动画。
- 点击“修改赴约信息”后恢复原表单高度与现有平滑滚动行为。
- 不改变接口、数据结构、默认关闭逻辑或管理后台。

## 交互与实现

在 `rsvp-client.js` 中提取可测试的成功态进入与退出函数。

进入成功态时按固定顺序执行：

1. 在隐藏表单前读取 `#rsvp` 的当前实际高度。
2. 把该高度写入 RSVP 区域的内联 `min-height`，锁住当前布局。
3. 给区域增加 `is-complete` 状态类。
4. 隐藏表单、显示成功卡片，并立即给成功卡片增加 `is-visible`，跳过等待 IntersectionObserver 的二次弹跳。
5. 用 `focus({ preventScroll: true })` 把无障碍焦点移到成功卡片，但不改变当前滚动位置。

`style.css` 中的 `.rsvp.is-complete` 使用网格布局和 `align-content: center`，让标题与成功卡片在保留高度内居中。成功卡片增加 `tabindex="-1"`，仅供程序聚焦，不进入正常 Tab 顺序。

退出成功态时先显示表单、隐藏成功卡片，再移除 `is-complete` 和内联 `min-height`。由于完整表单已恢复，其自然高度接管布局，不产生第二次塌缩；随后保留现有滚动到表单的行为。

## 测试

- 单元回归测试用可控 DOM 替身模拟“隐藏表单后区域高度变小”，确认进入函数在隐藏前捕获并锁定原高度。
- 测试成功卡片显示、`is-visible`、无滚动聚焦以及退出时状态清理。
- 运行全量 `npm test` 和 `npm run build`。
- 在 390×844 手机视口中拦截成功 API 响应，确认提交前后后续区块的文档位置不变，并目视检查成功卡片居中。

## 非目标

- 不把成功提示改成弹窗或浮层。
- 不保留跨页面刷新后的固定高度。
- 不调整成功卡片文案、颜色、接口返回值或 RSVP 表单字段。
