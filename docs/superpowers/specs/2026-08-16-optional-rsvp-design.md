# 可选 RSVP 模块设计

## 目标

将现有宾客登记、住宿登记和管理后台能力加入婚礼邀请函模板，同时保持 RSVP 默认关闭。未启用 RSVP 的用户仍可把项目作为纯静态 Cloudflare Pages 网站使用，不需要数据库、Secret 或服务端配置，也不会看到 RSVP 入口或错误。

## 部署架构

所有能力继续部署在 Cloudflare Pages：

- Vite 构建并托管婚礼邀请函与管理页面。
- Pages Functions 提供 RSVP 提交、读取、修改和管理员接口。
- Cloudflare D1 保存宾客数据。
- 网页与 API 使用同一个 `pages.dev` 域名，不引入跨域请求或第三方后端。

## 配置接口

在公开的婚礼配置中增加：

```js
rsvp: {
  enabled: false,
  apiUrl: '/api/rsvp',
}
```

`enabled` 是功能状态的唯一前端来源。模板仓库中的默认值必须为 `false`。

## 关闭状态

当 `rsvp.enabled` 为 `false` 时：

- 不显示 RSVP 表单、成功页或相关说明。
- 不显示浮动的“填写赴约信息”按钮。
- 不注册 RSVP 表单事件，不读取相关 localStorage，也不发起任何 RSVP API 请求。
- 普通页面的构建、预览和部署不依赖 D1、`ADMIN_PASSWORD` 或 `SESSION_SECRET`。
- `/admin/` 明确显示“RSVP 未启用”及启用文档入口，不尝试请求管理员接口。

模板保留 Functions 和迁移文件不会影响静态页面；只有启用后的 RSVP/API 路径才依赖 D1 和 Secret。

## 开启流程

用户运行：

```bash
npm run setup:rsvp
```

交互式脚本按顺序完成：

1. 检查 Node.js、依赖和 Wrangler。
2. 通过 Wrangler 打开浏览器完成 Cloudflare 登录。
3. 让用户选择现有 Pages 项目，或输入名称创建新项目。
4. 创建专属 D1 数据库，并将真实数据库 ID 写入 `wrangler.jsonc`。
5. 对绑定名 `DB` 应用仓库内全部 D1 迁移。
6. 生成高强度 `SESSION_SECRET`，不打印明文到最终摘要。
7. 提示用户输入 `ADMIN_PASSWORD`，输入过程不回显。
8. 将两个值写入目标 Pages 项目的 Secret。
9. 将 `rsvp.enabled` 改为 `true`。
10. 运行测试和生产构建，再通过 Wrangler 部署包含 `functions/` 的 Pages 项目。
11. 检查公开页面、RSVP 状态接口和管理后台登录页，最后输出邀请函与后台地址。

脚本必须可重复执行。已存在的项目、数据库、迁移或 Secret 应复用或更新，不得重复创建不可识别的资源。

## 错误处理

- 登录取消、项目名冲突、D1 创建失败、迁移失败、Secret 写入失败或部署失败时立即停止，并指出失败阶段及可安全重试的命令。
- 在远端配置完整且验证成功前，不把 `rsvp.enabled` 永久留在 `true`；失败时恢复原配置。
- 前端启用后若 API 返回“未配置”，显示面向站点所有者的简短错误，不丢失用户已经填写的表单内容。
- 管理后台不在浏览器保存管理员密码；登录凭证继续使用签名的 `HttpOnly` Cookie。

## README 要求

README 必须把 RSVP 明确标记为“默认关闭、可选启用”，并包含以下独立小节：

1. **适用人群**：不需要登记的用户无需阅读后续配置。
2. **开启前准备**：Node.js、Cloudflare 账号、Pages 项目与费用/免费额度提示。
3. **一条命令开启**：展示 `npm run setup:rsvp`，逐步说明脚本会创建和修改什么。
4. **启用后验证**：如何提交测试宾客、登录 `/admin/`、检查 D1 数据。
5. **日常更新部署**：说明使用 Wrangler 部署与 Git 集成部署的差异，避免混用导致配置漂移。
6. **关闭 RSVP**：如何隐藏功能，以及关闭不会自动删除宾客数据。
7. **彻底清理**：如何先导出数据，再删除 D1、Secret 和相关 Cloudflare 资源，并提示删除不可恢复。
8. **故障排查**：至少覆盖登录失败、缺少 DB 绑定、迁移未执行、Secret 缺失、部署后仍隐藏和管理后台无法登录。
9. **隐私与安全**：宾客电话和留言的用途、最小化收集、管理员密码要求与导出文件保护。

README 中所有命令必须可以直接复制运行，不使用未解释的占位符。需要用户替换的值必须紧邻命令说明来源和示例。

## 测试与验收

- 默认配置测试：构建成功，页面不显示 RSVP 区域和入口，不请求 RSVP API。
- 启用配置测试：表单显示并完成提交、修改、住宿日期校验和成功状态。
- API 测试：缺少 D1/Secret 时返回清晰配置错误；配置完整时保持现有安全与数据行为。
- 管理后台测试：关闭时显示说明；开启时支持登录、筛选、查看和导出。
- setup 脚本测试：用可控的命令执行器覆盖首次配置、重复执行与各阶段失败回滚。
- README 检查：文档中的标题、命令和关键故障提示由自动测试锁定，避免后续改动遗漏。
- 最终验证：运行完整测试、生产构建，并分别检查默认关闭与启用后的关键页面。

## 非目标

- 不迁移到 Cloudflare Workers 独立项目。
- 不引入腾讯 CloudBase 或其他第三方后端。
- 不为默认关闭状态创建远端数据库或 Secret。
- 不把不同模板使用者的数据集中到共享数据库。
